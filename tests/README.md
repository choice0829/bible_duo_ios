# 화면 시험 (헤드리스 크롬 모의 — 실기기가 아닙니다)

```
cd tests
npm install            # puppeteer-core, @sparticuz/chromium (인터넷 필요)
bash runreg.sh         # 전체(약 10분) → reg.log 에 기록, 끝에 요약 출력
node map1.mjs 펼침     # 하나만 (기기 이름 일부: 펼침 / 접힘 / 세로)
ROOT=/다른/폴더 node pc1.mjs   # 기본은 저장소의 www/
```
- 정상 종료는 `ALL PASS`, 실패는 `FAIL …`/`FAILS n`. `pc3`·`native3`은 합격·불합격 없이 수치만 보여 주는 점검용입니다.
- 한 번에 하나씩만 돌리세요(각 시험이 같은 크롬 프로세스를 정리하며 끝납니다). 화면 사진(`*.png`)·기록은 이 폴더에 생기지만 git에는 올라가지 않습니다.
- `rot4.mjs`(기기 168가지 조합, 5~8분)는 전체 목록에서 빼 두었습니다: `timeout 900 node rot4.mjs`. 전체 시험 중에는 아주 드물게 1건(듀오 펼침 + 위쪽 여백 48 조건에서 본문 위치를 0으로 읽음)이 시점 문제로 실패한 적이 있고, 단독으로 다시 돌리면 통과했습니다.

| 시험 | 확인하는 것 |
|---|---|
| `map1`, `map2`, `map3` | 모임 장소 지도(배치·등록·수정·삭제·백업·키보드·야간·오류 상황). `map3`은 화면 사진만 찍음 |
| `pc1`~`pc5` | 바이블 포토 카드(입력·미리보기·저장·글씨 배치·테마) — `fixtures/`의 시험용 사진 사용 |
| `kb1`, `native1`~`native6` | 키보드 대응, 앱 모드(`NATIVE`) 화면 배치·머리줄 |
| `hd1`, `desk2/5/8/9`, `rot4/9` | 머리줄·책상·본문 영역 기하(기기 여러 종류·회전) |
| `std3` | 번역 선택(설정 → 번역 선택) · AI 표준어 보기 |

지도 시험은 지도 바탕 요청(`https://tile.openstreetmap.org/…`)을 가로채 가짜 그림으로 응답하고, 앱↔Swift 메시지(`window.webkit.messageHandlers.bf`)는 흉내 냅니다. 그래서 **실제 지도 그림, 위치 권한, 주소 검색, 네이버 지도 열기는 시험하지 못합니다.**
