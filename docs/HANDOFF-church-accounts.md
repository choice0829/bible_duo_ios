# 인수 메모 — 교회 계정 · 교회별 게시판 · 설교 영상 탭 (구상 단계, 아직 코드 없음)

작성: 2026-11-24 (v73 기준). 이 문서는 **새 채팅에서 바로 이어서 시작**하기 위한 메모입니다. 아직 코드는 한 줄도 바뀌지 않았고, 아래 내용은 사용자 구상과 사전 조사(추정 포함)입니다.
기본 규칙(한국어·핵심 먼저·표 선호, 실기기에서 확인하지 못한 것은 따로 밝힘, 키·계정 정보는 채팅에 붙여 넣지 않기)은 `CLAUDE.md`를 따릅니다.

## 1. 사용자 구상 (원문 요지)
- **계정을 만들 때 교회를 등록**한다. 등록한 **교회별로 볼 수 있는 내용이 달라진다.**
- 예: '한사람교회'를 등록하면 **그 교회 안의 게시판·정보를 공유**할 수 있다.
- 교회가 **유튜브를 운영하면 설교 영상과 연동**한다. 예: 요한일서 1:1-4 설교 영상이 있으면, 노트 인덱스 탭처럼 본문 옆에 **빨간 배경에 재생 아이콘 탭**이 생기고, 누르면 **바로 유튜브로 연결**된다.
- 요청한 것: 작업 난이도·소요시간·배포에 추가로 필요한 것의 정리(아래 3~4장).

## 2. 지금 앱의 사실 (설계에 영향)
| 항목 | 현재 상태 |
|---|---|
| 서버 | **없음.** 하이라이트·설교노트·리뷰·설정은 모두 기기 안(`store`, localStorage). 기기 간 이동은 '데이터 백업'(글자 내보내기·불러오기)뿐 |
| 화면 주소 | 앱 안에서는 `bibleflip://app/index.html`(커스텀 스킴) → 서버로 `fetch` 할 때 CORS 허용 출처 문제, **쿠키 로그인은 맞지 않음 → 토큰을 헤더(Authorization)로 보내는 방식**으로 설계 |
| 웹↔앱 연결 | `window.webkit.messageHandlers.bf` 하나로 `open`(외부 앱·웹 열기, 앱 없으면 `fallback` 주소) · `share` · `loc` · `geocode` · `rgeo` · `mail` · `theme` · `error` 처리. 새 메시지(키체인 저장 등)는 `BibleFlip/ViewController.swift` 의 `userContentController` 에 추가 |
| 외부 링크 열기 | `open` 메시지가 https 주소를 열면 유튜브 앱이 있을 때 그쪽으로 열릴 가능성이 높음(실기기 확인 필요). 허용 스킴은 `https · http · nmap · tel` |
| 노트 탭(참고 구현) | `www/app.js` 의 `refreshTabs()`(`tabsEl = #note-tabs`, 클래스 `.nt-tab`, `noteColor()`): 노트마다 본문이 처음 나오는 줄 높이에 탭을 놓고, 왼쪽·오른쪽 가장자리에 겹치지 않게 쌓고, 넘치면 `+N` 하나로 줄임. **펼친(두 쪽) 화면에서만 보임**(`!pg.g.spread` 이면 그리지 않음) |
| 노트 자료 구조 | `bf.notes`: `{ id, title, body, date, bk, c1, v1, c2, v2, ts }` (책·장·절 범위) → 설교 영상도 같은 범위 구조를 쓰면 탭 배치 코드를 재사용 가능 |
| 서명·배포 | 서명 없는 IPA를 Sideloadly로 설치(무료 Apple ID, **7일마다 재서명**, 사용자마다 Windows PC 필요) → **다른 교회 사용자에게는 현실적이지 않음** |

## 3. 기능별 난이도·소요시간 (집중 작업 기준 **추정**, 실제 측정값 아님)
| 기능 | 난이도 | 소요 |
|---|---|---|
| 계정·교회 등록·초대코드 가입·권한(관리자/성도), 교회별 데이터 분리 | 상 | 1.5~3주 |
| 설교 영상 탭(관리자가 영상 주소·구절 입력 → 빨간 재생 탭 → 유튜브 열기) | 중 | 3~6일 |
| 게시판·공지(글·댓글) | 중상 | 1.5~2.5주 (사진·신고·차단 추가 시 +1주) |
| 교회 관리자 화면 | 중 | 1~2주 (처음엔 서버 대시보드로 대체 가능) |
| 유튜브 자동 연동(채널 영상 가져오기 + 제목에서 구절 인식) | 중상 | 1~2주 (구절 인식은 틀릴 수 있어 관리자 확인 단계 필요) |
| 개인정보·약관·배포 준비·심사 | 중 | 1~3주 (심사 대기는 외부 요인) |

합계(추정): 영상 탭까지 최소판 약 3~5주 / 게시판까지 약 6~9주 / 자동 연동·배포 준비까지 약 9~13주.
이 샌드박스는 외부 서버(Supabase 등)에 접속할 수 없어, **서버 설정과 실기기 확인은 사용자와 주고받아야** 하므로 더 걸릴 수 있습니다.

## 4. 배포에 추가로 필요한 것
- **Apple 개발자 프로그램**(유료): 앱스토어 표시 기준 ₩129,000/년. 가입하면 TestFlight로 외부 테스터 최대 10,000명 초대 가능. 조직 명의는 법인 상태·D-U-N-S 번호 필요, 개인 가입이면 본인 법적 이름이 판매자로 표시됨.
  - https://developer.apple.com/kr/programs/ · https://developer.apple.com/kr/support/enrollment/ · https://apps.apple.com/kr/app/apple-developer/id640199958
  - 지금 빌드(`.github/workflows/build-ios.yml`)는 **서명하지 않는 IPA**라서, TestFlight용으로는 인증서·프로비저닝·App Store Connect 키 설정과 워크플로 변경이 추가로 필요(키는 **GitHub Secrets에만** 넣고 채팅에는 올리지 않기).
- **서버**: 호스팅(Supabase 등: 인증 + DB + 행 단위 접근 규칙) · 무료 한도 초과 시 요금 · 인증/재설정 메일 발송 설정 · 개인정보 처리방침·지원 페이지를 올릴 웹 주소(도메인).
- **개인정보**: 교회 소속은 종교 관련 정보라 개인정보보호법상 **민감정보로 볼 소지**가 큼 → 별도 동의·보관·삭제 기준 필요할 수 있음. **법률 전문가 확인 필요**(이 메모는 법률 판단이 아님). 교회 멤버 목록·소속은 같은 교회 안에서만, 최소한만 보이게.
- **Apple 심사**(작성자가 아는 규정이며 **제출 전 최신 가이드라인 확인 필요**): 사용자 글(게시판)은 신고·차단·부적절 콘텐츠 대응·운영자 연락처가 필요, 앱 안에서 계정 삭제 가능해야 함, 개인정보 처리방침 주소, 심사용 시험 계정. 구글 등 다른 서비스 로그인을 넣으면 추가 요건이 생길 수 있음(이메일 로그인만이면 해당 없음으로 알고 있음).
- **유튜브 연동**: Google Cloud 프로젝트·API 키(서버에만 보관). 기본 할당량은 하루 10,000 단위, `search.list` 는 호출당 100, `playlistItems.list` 는 1 → **채널의 업로드 목록(playlistItems)으로 가져오면 부담이 거의 없음**. 할당량을 더 늘리려면 YouTube API 서비스 약관 준수 심사가 필요. 영상은 **링크만 열기**(임베드·재생 안 함)라 약관 부담이 작음.
  - https://developers.google.com/youtube/v3/determine_quota_cost · https://developers.google.com/youtube/v3/guides/quota_and_compliance_audits
- **운영**: 교회 개설 승인·스팸 방지, 서버 백업, 문의 창구, 신고 처리.
- **무료 Apple ID 서명**: 푸시·iCloud·Apple로 로그인 등 일부 기능을 못 쓰는 것으로 알고 있음(미확인) — 설계 전에 확인.

## 5. 설계 초안 (제안일 뿐, 아직 사용자 확정 아님)
- 서버: Supabase(Postgres + Auth + 행 단위 접근 규칙). 표 개요: `churches`(이름, 개설자, 상태) · `memberships`(사용자, 교회, 역할: 관리자/성도, 상태) · `sermons`(교회, 유튜브 영상 ID, 책·장·절 범위, 제목, 설교자, 날짜) · `posts` · `comments`. **모든 표에 교회 ID, 접근 규칙으로 같은 교회 사람만 읽기·쓰기.**
- 로그인: 이메일(+비밀번호 재설정)부터. 토큰은 **아이폰 키체인**에 보관(Swift 쪽 새 메시지 추가), 웹은 Authorization 헤더. 구글 등 소셜 로그인은 앱 안 웹뷰에서 막히는 것으로 알고 있어 `ASWebAuthenticationSession` 이 필요(후순위).
- 오프라인 우선 유지: 가입한 교회의 설교 영상 목록은 기기에 저장해 두고 오프라인에서도 탭이 보이게.
- 설교 영상 탭: `refreshTabs()` 배치 코드 재사용, 빨간 배경 + 재생 아이콘, 눌러 `open` 메시지로 `https://youtu.be/<영상ID>`(필요하면 `?t=` 시작 시각) 열기. **정해야 할 것:** 노트 탭과 같은 가장자리에서 겹칠 때 규칙, 한 구절에 영상이 여러 개일 때(목록 팝업), **접은/세로 화면**(탭이 안 보이는 화면)에서의 표시 방법.

## 6. 권장 단계 (사용자에게 제안한 순서)
1. **최소판**: 이메일 로그인 → 교회 가입(초대코드) → 관리자가 영상 주소+구절 입력 → 빨간 재생 탭. (서버 대시보드로 관리)
2. 게시판·공지 → 교회 관리자 화면.
3. 유튜브 자동 연동(채널 업로드 목록 → 구절 후보 → 관리자 확인).
4. 병행: Apple 개발자 가입·TestFlight·개인정보 처리방침·심사 준비.

## 7. 아직 정하지 않은 것 (새 채팅에서 먼저 물을 것)
- **교회 개설을 누구나 할 수 있게 할지, 사용자가 승인하는 방식으로 할지**(스팸 가입 방지 방식이 달라짐) ← 마지막으로 물어본 질문, 미답변
- 교회 가입 방식(초대코드 / 관리자 승인 / 둘 다), 한 사람이 여러 교회에 속할 수 있는지
- 게시판 범위(글만 / 댓글 / 사진), 공지와 일반 글 구분
- 설교 영상 입력 방식: 처음은 수동, 자동 연동은 나중에?
- 누가 쓰는가(본인 교회만 / 여러 교회), 대략적 사용자 수 → 서버 요금·배포 방식(TestFlight vs App Store)에 영향
