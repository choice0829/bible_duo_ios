# 문의하기 · 후원하기 설정 안내서 (v69)

앱 설정 화면에 **문의하기**(제목·내용·사진 → 메일)와 **후원하기**(앱 안 결제)가 들어갔습니다. 화면과 아이폰 쪽 코드는 완성되어 있지만, **아래 두 가지는 택 님이 정해 주셔야 실제로 동작합니다.**

## 한눈에 보기

| 항목 | 지금 상태 | 필요한 것 |
|---|---|---|
| 문의하기 화면·사진 첨부·메일 작성 창 연결 | 코드 완료(PC 모의 시험 통과), 받는 주소 입력 완료 | 실기기 확인 |
| 후원하기 화면·결제 코드 | 코드 완료(PC 모의 시험 통과) | Apple 개발자 프로그램 가입 + App Store Connect에 후원 상품 만들기 |
| 사이드로드(Sideloadly)로 설치한 앱 | 문의하기는 **동작**, 후원하기는 **동작하지 않음**(안내 문구만 보임) | 후원 확인은 TestFlight/App Store 설치 앱에서 |

> Apple ID 정보·API 키·지도 키는 채팅이나 저장소에 붙여 넣지 마세요. (받는 메일 주소는 아래 설명처럼 저장소에 적히므로, 전용 주소를 권장합니다.)

## 1. 문의하기

### 1-1. 받는 메일 주소
- 현재 받는 주소는 `choice.seon@gmail.com` 입니다(2026-11-23 택 님이 알려 주심). 바꾸려면 `www/app.js` 안의 한 줄 `const INQUIRY_EMAIL = '…';` 의 따옴표 사이만 고치면 됩니다. 비워 두면 문의하기 화면에 「받는 메일 주소가 아직 설정되지 않아 보낼 수 없습니다」라고 나오고 보내지지 않습니다.
- **주의:** 이 저장소는 공개이고, 주소는 앱 파일 안에도 들어갑니다. 즉 **주소는 누구나 볼 수 있습니다**(스팸·광고 메일이 올 수 있음). 문의 전용 주소로 바꾸고 싶으시면 위 한 줄만 고치고 새 버전으로 다시 설치하면 됩니다.

### 1-2. 동작 방식
1. 설정 › 문의하기에서 제목·내용을 쓰고, 사진은 최대 3장 붙입니다(큰 사진은 앱이 긴 변 1600px 안쪽으로 줄입니다).
2. 「메일로 보내기」 → 아이폰 **기본 메일 작성 창**이 받는 사람·제목(`[앱 문의] …`)·내용·사진이 채워진 채 열립니다.
3. 내용을 확인하고 **메일 작성 창의 보내기**를 한 번 더 눌러야 전달됩니다. 앱 버전과 화면 크기가 내용 끝에 자동으로 적힙니다(안내 문구에도 적어 두었습니다).
4. 보낸 뒤 앱 화면의 제목·내용·사진은 비워지고, 취소·임시 저장·실패 때는 쓰던 글이 남습니다.

### 1-3. 메일 계정이 없는 아이폰
아이폰의 **메일 앱에 계정이 없으면 메일 작성 창을 열 수 없습니다**(Gmail 앱만 쓰는 경우 등). 이때 앱은 ① 받는 주소 표시·복사 ② 제목·내용 복사 ③ 「기본 메일 앱으로 열기」(mailto 링크, **사진은 붙지 않음**)를 보여 줍니다. 사진까지 보내려면 설정 › 메일에서 계정을 추가해야 합니다.

## 2. 후원하기

### 2-1. 화면에 적은 내용 (택 님이 말씀하신 후원 목적)
- 후원금 쓰임: ① **개역개정과 다양한 번역본 추가** ② **세계 어디서나 쓸 수 있는 앱 개발비**
- 함께 밝힌 것: 후원은 **전적으로 선택**이며 기능·광고와 무관함 / 후원이 특정 번역본의 추가나 시기를 **약속하는 것은 아님**(번역본은 저작권자의 허락을 받은 경우에만 추가) / 결제는 Apple ID로, Apple 수수료를 뺀 금액이 전달됨 / 기부금 영수증은 발급되지 않음.
- 문구를 고치려면 `www/app.js`의 `showSupport()` 안 글을 바꿉니다.

### 2-2. 꼭 알아 두실 점
- **앱 안 결제(StoreKit)는 사이드로드 앱에서 동작하지 않습니다.** 상품은 Apple이 심사·승인한 앱에서만 불러올 수 있습니다. 지금 방식(Sideloadly)으로 설치한 앱에서는 「지금은 후원할 수 있는 상품이 없습니다…」 안내만 보입니다.
- 후원을 실제로 받으려면 **유료 Apple 개발자 프로그램 가입**과 **App Store(또는 TestFlight) 배포**가 먼저입니다. 가입비·수수료율·세금 처리는 Apple 공식 안내에서 현재 조건을 확인해 주세요(제가 지금 값을 확인해 드리지 못했습니다).
- App Store 심사 지침은 앱 안에서 **외부 링크·계좌로 후원을 받는 방식**을 제한하는 경향이 있어, 이 앱은 처음부터 앱 안 결제로 만들었습니다. 심사 시점의 지침은 다시 확인이 필요합니다.
- 후원은 **소모성** 상품이며 결제해도 앱의 어떤 기능도 열리거나 닫히지 않습니다(심사에서도 이 점이 중요합니다).

### 2-3. App Store Connect에서 만들 후원 상품 (소모성)
앱 레코드를 만든 뒤 「앱 내 구입」에서 아래 3개를 만듭니다. **제품 ID는 코드(`BibleFlip/SupportBridge.swift`의 `productIDs`)와 글자까지 같아야** 합니다.

| 제품 ID | 유형 | 권장 표시 이름 | 가격 |
|---|---|---|---|
| `com.choice0829.bibleflip.support.small` | 소모성 | 작은 후원 | 택 님이 가격표에서 선택 |
| `com.choice0829.bibleflip.support.medium` | 소모성 | 보통 후원 | 〃 |
| `com.choice0829.bibleflip.support.large` | 소모성 | 큰 후원 | 〃 |

- 가격은 화면에 **App Store가 알려 주는 가격이 그대로** 표시됩니다(앱에 금액을 적어 두지 않음). 금액은 가격표에서 고르시면 됩니다.
- 상품마다 한국어 표시 이름·설명, 심사용 화면 캡처가 필요합니다.
- 앱 이름을 ‘선한’으로 바꾸고 번들 ID(`com.choice0829.bibleflip`)를 바꾸게 되면 **제품 ID도 함께 맞춰야** 합니다(상품 ID는 번들 ID와 달라도 동작하지만, 코드·App Store Connect 두 곳이 같아야 합니다).
- 「유료 앱 계약」 및 세금·은행 정보 입력이 끝나기 전에는 상품이 앱에 나타나지 않을 수 있습니다.

### 2-4. 세무·법률 (전문가 상담 권고)
아래는 제가 판단해 드릴 수 없는 영역입니다. **세무사·변호사 상담**을 권합니다.
- 후원금(앱 내 결제 수입)의 소득 분류·신고, 사업자등록 필요 여부, 부가가치세
- 후원금 사용처를 화면에 적어 두는 것(번역본 추가·개발비)과 관련해 지켜야 할 법적 표현
- **개역개정 등 번역본 본문 사용**은 저작권자(예: 대한성서공회)의 사용 허락·조건 확인이 먼저입니다. 허락 전에는 앱에 넣을 수 없고, 후원 문구도 추가를 보장하는 것처럼 보이지 않게 두었습니다.

## 3. 실기기에서 확인할 것 (PC 모의로는 확인하지 못했습니다)

| 번호 | 확인 | 어디서 |
|---|---|---|
| 1 | 설정 › 문의하기 › 제목·내용 입력 후 「메일로 보내기」 → 메일 작성 창이 받는 사람·제목·내용으로 채워져 열린다 | Sideloadly 설치 앱 |
| 2 | 사진 추가(앨범에서 고르기) → 작은 그림으로 보이고, 메일에 첨부로 붙는다. 3장 제한·× 로 빼기 | 〃 |
| 3 | 메일 작성 창에서 보내기·취소·임시 저장 → 앱 화면에 알맞은 안내가 나온다 | 〃 |
| 4 | 메일 앱에 계정이 없을 때 대체 방법(주소 복사·기본 메일 앱 열기)이 보인다 | 〃 |
| 5 | 키보드가 올라와도 내용 칸·보내기 단추가 가려지지 않는다(듀오 펼침·접힘 모두) | 〃 |
| 6 | 후원하기 화면: 목적 글이 잘 보이고, 사이드로드 앱에서는 「후원할 수 있는 상품이 없습니다」가 나온다 | 〃 |
| 7 | 상품을 만든 뒤: 상품 단추(이름·가격)가 보이고, 누르면 Apple 결제 창이 열린다. 취소·완료 때 안내가 나온다 | TestFlight(샌드박스) 또는 App Store 설치 앱 |
