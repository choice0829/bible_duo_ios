# 책장성경 (웹앱) — 아이폰에 설치하기

Mac이 없어도 됩니다. 이 폴더를 인터넷에 한 번 올리면, 아이폰 Safari에서 **홈 화면에 추가**해 앱처럼 쓸 수 있습니다.
한 번 열어 두면 인터넷 없이도 열립니다.

## 1단계. 인터넷에 올리기 (둘 중 하나)

### A. Netlify Drop (가장 간단)

1. 컴퓨터 브라우저에서 <https://app.netlify.com/drop> 접속 → **먼저 로그인(무료 가입)** 하세요.
   로그인 없이 올리면 임시 비밀번호가 걸린 주소가 만들어집니다.
2. 압축을 푼 `bible-pwa` 폴더(또는 zip 파일)를 화면의 드롭 영역에 끌어다 놓습니다.
3. `xxxx.netlify.app` 형태의 주소가 나옵니다.
4. 사이트가 **공개** 상태인지 확인하세요. 팀 설정이 "기본 비공개"이면 아이폰에서 열 때 로그인이 필요할 수 있습니다.

### B. GitHub Pages

1. GitHub에 새 저장소를 만들고 이 폴더의 파일을 모두 올립니다(폴더 구조 그대로).
2. Settings → Pages → Branch를 `main` / `(root)`로 지정하면 `https://계정.github.io/저장소/` 주소가 생깁니다.

> 반드시 **https** 주소여야 오프라인 저장(서비스 워커)이 동작합니다. 위 두 방법은 모두 https입니다.

## 2단계. 아이폰에 설치

1. 아이폰 **Safari**로 위 주소를 엽니다. (Chrome 등 다른 브라우저는 안 됩니다)
2. 아래 **공유 버튼(네모에 화살표) → 홈 화면에 추가**
3. 홈 화면의 **책장성경** 아이콘으로 실행합니다. (주소창 없는 전체 화면으로 열립니다)
4. 처음 한 번은 인터넷이 연결된 상태에서 열어야 본문이 저장됩니다.

## 사용법

- **접은 화면:** 한 장(chapter)씩 위아래로 스크롤해 읽고, 옆으로 밀거나 가장자리를 누르면 다음·이전 장이 슬라이드로 넘어옵니다. 장 맨 아래의 버튼으로도 이동하며, 책의 끝에서는 다음·이전 책으로 이어집니다.
- **펼친 화면(두 쪽):** 좌우 가장자리를 누르거나 끌면 책 넘김 효과로 넘어갑니다.
- 화면 맨 위 왼쪽에 **책 이름(굵게)**이 항상 표시됩니다. 누르면 책·장을 고르고, 그 아래 본문 바로 위의 작은 아이콘 버튼 돋보기(검색) · 톱니바퀴(설정: 글자 크기·**글씨체**·테마·화면 구성) · 책갈피(하이라이트: 저장한 본문 모아 보기) · 노트(설교노트)를 씁니다. 본문의 각 장 제목은 책 이름 없이 `11장`처럼 표시됩니다.
- **하이라이트·표시(낱말 단위):** 본문의 낱말을 **길게 누르면**(누른 채 끌면 범위가 넓어짐) 또는 화면 **가운데를 한 번 누르면** 그 낱말이 골라지고 도구 상자가 뜹니다.
  - 모양: `형광` · `동그라미` · `네모` · `물결` · `밑줄` / 펜: `싸인펜` · `색연필`(종이 결이 보이는 질감) / 색 5가지(노랑·초록·파랑·분홍·주황)
  - **여러 낱말 선택:** 하나를 고른 뒤 다른 낱말을 **눌러서 계속 더할 수 있고**(다른 절·다른 쪽도 가능, 붙어 있는 낱말은 한 범위로 합쳐짐), 이미 고른 낱말을 다시 누르면 그 낱말만 빠집니다. 고르는 동안에는 화면 어디를 눌러도 낱말 선택이 우선이며(쪽 넘김 탭은 잠시 멈춤), `닫기`를 누르면 끝납니다.
  - 모양 버튼을 누르면 바로 표시됩니다. 같은 표시를 다시 누르면 지워집니다. `시작 ◂▸` `끝 ◂▸`는 범위를 낱말 하나씩 줄이고 늘리며, `절 전체`는 한 절 전체를, `지우기`는 고른 범위의 표시를 지웁니다.
  - 표시는 한 절 안에서만 하고, 글씨가 있는 부분에만 입혀집니다(줄 전체가 아님). 형광은 서로 겹치지 않게 새로 칠한 것이 덮어씁니다.
  - `하이라이트` 버튼: 표시한 구절을 모아 보고, 누르면 그 본문으로 이동, ✕로 그 구절의 표시를 모두 지웁니다. 예전의 절 전체 하이라이트는 자동으로 노란 형광(싸인펜)으로 옮겨집니다. (기기에 저장되므로 앱 데이터를 지우면 사라집니다)
- **설교노트:** 메뉴의 **노트 아이콘**을 누르면 노트 목록이 열리고, 오른쪽 위 **연필 ✎**로 새 노트를 씁니다. 순서는 **제목 → 설교 본문 → 노트 내용**입니다.
  - 설교 본문은 `책` → `시작`(장·절) → `끝`(장·절)을 선택칸에서 고르거나, 위의 `바로 입력`에 `요 3:16-21` · `시 23` · `창 1:1-2:3`처럼 적으면 자동으로 채워집니다. `지금 읽는 곳` 버튼은 현재 읽는 절을 넣어 줍니다.
  - `작성 완료`를 누르면 저장되고, 그 본문에 **노트 표시**가 생깁니다.
    - 펼친 화면에서는 책 **왼쪽 옆면에 인덱스 탭**이 붙습니다. 탭에는 노트 제목 앞 5글자가 세로로 적히고, 그 노트 본문이 처음 나오는 줄 높이에 놓입니다. 한 화면에 탭이 너무 많으면 `+N` 탭으로 줄어들고 누르면 노트 목록이 열립니다. 왼쪽 여백(가로 위치)을 아주 좁게 줄이면 탭은 숨습니다.
    - **탭을 누르면** 그 노트의 본문만 밝게 남고 나머지 글은 흐려지며, 아래에 **노트 미리보기 카드**(제목·본문 구절·날짜·내용 앞부분)가 뜹니다. 카드의 **노트 열기 ›**를 누르면 노트 전체가 열리고, **본문만 보기**는 카드만 접습니다. 바깥을 누르거나 같은 탭을 다시 누르거나 책장을 넘기면 원래대로 돌아옵니다(바깥을 누른 한 번은 닫기만 하고 책장은 넘기지 않습니다). 글을 흐리게 하는 것은 글자 투명도뿐이라 쪽 나누기·글자 위치는 바뀌지 않습니다.
    - 접힌 화면에서는 장 제목 밑의 노트 칩으로 표시됩니다(칩을 누르면 노트가 열립니다). 노트마다 색이 달라 서로 구분됩니다.
  - 목록에서 노트를 누르면 내용을 보고(`이 본문으로 이동` · 본문 보기 · 수정 · 삭제), 쓰는 도중에는 입력할 때마다 임시 저장되어 앱이 닫혀도 `이어 쓰기`로 이어서 쓸 수 있습니다.
  - 노트는 이 기기의 이 앱 안에 저장되며, `데이터 백업`에도 함께 담깁니다.
- 여백 기본값: 펼침 윗 여백 96 · 가로 위치 52 · 아래 여백 20, 한 쪽 윗 여백 150. `설정` → **고급설정**에서 각 항목의 설명을 보며 조절하고 `되돌리기`로 기본값을 복원합니다.
- **검색:** `요 3:16`, `시편 23`, `고전 13:4`, `요한복음 3장 16절`처럼 구절을 입력하면 바로 이동하고, `사랑`, `여호와 목자`처럼 낱말을 입력하면 본문을 검색합니다(낱말이 여러 개면 모두 들어간 절만 표시). 결과를 누르면 그 절로 이동하며 해당 절이 잠깐 노란색으로 표시됩니다. 키보드의 검색(Enter) 키는 첫 결과로 이동합니다.
- 절마다 새 줄에서 시작합니다.
- **접힌 상태(좁은 화면)는 한 쪽, 펼친 상태(넓은 화면)는 두 쪽**으로 자동 전환되며, 읽던 절은 유지됩니다.
- 읽던 위치와 설정은 기기에 자동 저장됩니다. 하이라이트·설교노트·읽던 위치는 이 기기의 이 앱 안(주소별)에만 있으므로, 앱 주소를 옮기거나 앱을 지우기 전에 `설정` → `고급설정` → `데이터 백업`에서 내보내 두세요. (복사한 글을 새 앱의 같은 화면에 붙여 넣으면 복원됩니다)

## 알아 둘 점

- **기종별 자동 보정(v25):** 처음 설치한 기기는 윗·아래 여백과 가로 위치를 화면 크기와 안전영역(노치·다이내믹 아일랜드·홈 막대)에 맞춰 자동으로 정합니다. 폭 700px 이상이거나, 가로로 눕혀 폭 640px 이상이면 두 쪽으로 펼칩니다(아이폰 SE 가로 포함). 높이가 500px보다 낮은 가로 화면은 책 이름·메뉴를 작게 줄여 본문 줄 수를 늘리고, 노치 쪽 좌우 안전영역은 비웁니다. 책 이름이 길어 넘치면 글자 크기를 알아서 줄입니다. 고급설정에서 직접 바꾼 값은 자동값보다 우선하며, **되돌리기**를 누르면 저장한 값을 지우고 자동값으로 돌아갑니다. 아이폰 듀오 펼침은 예전과 같은 값(윗 96 · 가로 위치 52 · 아래 20)입니다.
- **쪽 나누기 저장:** 한 번 계산한 쪽 나누기는 기기에 저장해 두었다가, 같은 책·화면 크기·글씨체이면 바로 불러옵니다(시편·창세기 같은 긴 책도 두 번째부터 즉시 열림). 글씨체 파일이 다 준비되기 전에 나눈 결과는 저장하지 않으며, 저장된 결과가 이 기기에서 맞지 않으면 자동으로 버리고 다시 나눕니다.
- **아이폰 듀오에서의 기준:** 자동 모드는 화면 폭이 700px 이상이면 두 쪽으로 봅니다. `설정` → `고급설정` 아래쪽 '화면 정보'에 현재 화면 크기가 표시되니, 펼쳤을 때 한 쪽으로 나오면 `app.js` 맨 위의 `AUTO_SPREAD_MIN_WIDTH` 값을 낮추거나 설정에서 "펼침(두 쪽)"을 직접 고르세요.
- **글씨체:** 기본 명조·기본 고딕(아이폰 내장), 나눔명조·고운바탕·고운돋움·나눔고딕(앱에 포함, `fonts/`). 글씨체를 바꾸면 쪽 나누기가 다시 되고 읽던 절은 유지됩니다. 글꼴 라이선스(SIL OFL)는 `fonts/LICENSE.txt`.
- **검증 범위:** 데스크톱용 헤드리스 크로미움(가상 화면 390×844, 1032×760)에서 쪽 나누기·책 넘김·접기/펼치기 위치 유지를 확인했습니다. **실제 아이폰 Safari에서는 아직 확인하지 못했습니다.** 글꼴(애플명조)이 달라 쪽 수가 조금 다를 수 있습니다.
- **본문 누락 8곳:** 한글 본문이 빠진 절이 있습니다. (삼상 30:31, 왕상 1:28, 왕상 2:9, 시 45:13, 시 72:20, 행 13:51, 고후 13:14, 계 12:18) 실사용 전 원문과 대조가 필요합니다.
- **저작권:** 개역한글은 대한성서공회가 사용 허가 없이 쓸 수 있다고 안내한 것으로 알려져 있으나, 배포 전 공회에 직접 확인하세요. 책 넘김 라이브러리 page-flip은 MIT 라이선스입니다(`lib/page-flip.LICENSE`).
- **화면 돌리기·접기 안정화(v26·v27):** 세로로 둔 한 쪽 화면에서는 책 이름·메뉴 줄의 실제 높이(상태 표시줄 자리 포함)를 계산해 본문이 항상 그 **아래**에서 시작합니다(메뉴 단추가 본문 첫 줄을 덮던 문제). 가로↔세로로 돌리거나 접고 펼칠 때는 ① 바뀐 걸 느끼는 즉시 화면을 가리고 ② 화면 크기·안전영역 값이 0.25초 이상 같게 읽힐 때까지(최대 3초) 기다렸다가 ③ 돌리기 직전에 읽던 위치 그대로 책을 다시 만들고 ④ 다 만든 뒤에도 실제로 그려진 위치가 계산과 맞는지 세 번 확인해 어긋나 있으면 한 번 더 만듭니다. 안전영역 값만 늦게 바뀌어도(알림 이벤트가 없음) 1.5초마다 확인해 따라갑니다. 책장 라이브러리가 회전할 때마다 쌓아 두던 크기 감지 처리기를 정리해 오류가 누적되지 않게 했고, 회전 뒤 화면 배율이 1이 아닌 채 남으면 배율을 1로 되돌립니다. **돌렸다 되돌리면 화면이 작아져 위·왼쪽에 붙던 현상**은 아이폰이 세로 화면에 남은 폭 넓은 책을 보고 '화면에 맞춰 축소'한 뒤 가로로 돌아와도 풀지 않는 것으로 보고, ① 돌리는 순간 옛 방향용 책을 CSS로 즉시 숨기고 ② viewport에 배율 고정(`minimum-scale=1, maximum-scale=1, shrink-to-fit=no`)을 넣었으며 ③ 그래도 배율이 1이 아니면 viewport 태그를 갈아 끼워 1로 되돌린 뒤 다시 만듭니다. 책장이 접힌 채 멈추는 현상은 ④ 다시 만드는 동안·만든 뒤에는 손가락 입력과 끌기 상태를 버리고 ⑤ 접힌 채 3초 넘게 멈추면 책을 다시 만드는 것으로 막았습니다. 설정 → 화면 진단에 `회전·접기 N번(다시 만듦 M번) · 마지막: …`, `안전영역 · 머리줄 아래 · 본문 시작`, `배율 · 보이는 영역 · innerWidth · 문서 폭 · 기기` 값이 남으니, 그래도 이상하면 그 화면을 캡처해 주세요.

- **번역 선택(v31, 이전 이름 '쉬운 말 보기'):** 머리줄 오른쪽 끝의 **번역 선택** 단추(줄 두 개와 체크 모양)를 누르면 '번역 선택' 창이 열리고, 번역 목록이 **체크박스**로 나옵니다. 지금 고를 수 있는 것은 **AI 표준어 번역** 하나이며, 체크하면 그 아래에 보기(창세기 1장 1절)와 안내문(참고용 글·설교 전 검토 권고)이 나타나고 개역한글 각 절 바로 아래에 표준어로 풀어 쓴 문장이 작은 글씨로 함께 나옵니다. (예: 태초에 하나님이 천지를 창조하시니라 → 태초에 하나님이 하늘과 땅을 창조하셨다.) **개역개정·현대인의성경·쉬운성경**은 자리만 있고 체크할 수 없으며, 목록 아래 참고문으로 '추후 업데이트될 예정'이라고 안내합니다(코드의 `TRANSLATIONS`에 `ready: true`로 바꾸고 본문을 넣으면 선택할 수 있게 확장 가능). 이전의 '준비된 곳' 목록은 없앴습니다. 체크를 바꿔도 창은 닫히지 않고 뒤의 본문만 다시 만들어지며 읽던 위치는 유지됩니다. 펼친 화면은 쪽 나누기에 풀이 분량까지 넣어 다시 나누고, 접은 화면은 절마다 아래에 붙습니다. 풀이는 다른 번역본을 가져온 것이 아니라 개역한글 본문을 바탕으로 직접 옮겨 쓴 **참고용 글**이며, 낱말 선택·하이라이트는 개역한글 본문에만 적용됩니다. 풀이는 `data/std/<책 id>.json`에 `{ "id": "gen", "v": 1, "c": { "1": { "1": "문장", "2": "문장" } } }` 형식으로 담고(장·절 번호는 문자열), 준비된 곳은 `data/std/index.json`(`{ "v": 1, "books": { "gen": [1] } }`)에 적습니다. 목록에 없는 책·장은 개역한글만 보이고, 책 파일의 `v`를 올리면 쪽 나누기 저장분이 새로 계산됩니다. 풀이 파일은 `sw.js`가 '네트워크 먼저'로 받아 오며(설치할 때 목록의 책을 모두 미리 저장), 지금 들어 있는 곳은 모세오경 전체(창·출·레·민·신)와 시편 23편 · 요한복음 3장(시험용)입니다.
- **머리줄 위치·책 넘김 범위(v32):** 펼친 화면에서 책을 넘길 때 올라오는 책장 귀퉁이가 제목·메뉴(머리줄)까지 올라와 글자를 가리던 것을, 책 영역(`#stage`)을 머리줄 아래에서 시작하게 하고 그 바깥은 잘라내(`overflow: clip`) 머리줄에는 닿지 않게 고쳤습니다. 본문 글자의 화면상 위치·쪽 나누기는 그대로입니다(저장된 쪽 나누기도 그대로 쓰임). 메뉴 단추 5개(검색·설정·책갈피·설교노트·번역 선택)는 오른쪽으로 옮겼습니다. 펼친 화면은 제목 오른쪽 끝에 한 줄로, 접은(좁은) 화면은 제목 아래 둘째 줄의 오른쪽 끝에 놓입니다. 접은 화면의 세로 스크롤은 원래 머리줄 아래에서 시작해 바뀐 것이 없습니다. 회전·접기 안정화 점검은 책 영역의 시작 높이(`stageTop`)를 기준으로 하도록 맞췄습니다.
- **책상 + 책 카드(v33):** 머리줄(책 이름·메뉴) 영역을 '책상'으로, 본문을 그 위에 놓인 '책 카드'로 구분했습니다. 책 카드는 윗모서리가 둥글고 책상 위로 살짝 뜬 그림자가 있으며, 책장이 넘어갈 때 들린 귀퉁이도 이 카드 안에서만 보입니다(펼침은 책 영역, 접힘은 위아래로 읽는 장 영역). 책상 색은 테마(종이·세피아·야간)를 따라가고, 맨 위에서 비추는 은은한 빛이 들어갑니다. `설정` → **책상 질감**에서 **단색·린넨(기본)·나무결·가죽** 중 고를 수 있으며(책을 다시 만들지 않고 바로 바뀜), 선택은 `데이터 백업`에도 담깁니다. 질감은 CSS 안의 작은 SVG 무늬(`feTurbulence`)라 별도 이미지 파일이 없고, 아이폰 상태 표시줄 색(theme-color)도 책상 색으로 맞춥니다. 본문 글자의 위치·쪽 나누기는 v32와 같습니다. 코드에서는 `app.js`의 `DESKS`·`DESK_DEFAULT`, `style.css`의 `body.desk-*` 블록을 고치면 됩니다. **(v34)** 듀오 펼침의 오른쪽 안전영역처럼 책 바깥에 남는 여백이 흰색으로 보이던 것을, 바탕 전체(`<html>`)에도 같은 테마·책상 클래스를 달아 책상 색(과 질감)으로 칠하도록 고쳤습니다. 앱 배경색(`theme-color`, `manifest`의 `background_color`)도 책상 색(#DCD4C2)으로 바꿨습니다. 단, 시스템이 그리는 영역은 색만 따라가고 질감은 기기에 따라 안 보일 수 있으며, `manifest` 색은 앱을 홈 화면에 다시 추가해야 반영됩니다. **(v36)** 듀오에서 앱 창(867px) 오른쪽 바깥의 상태 아이콘 영역(약 84px, 와이파이·시계·배터리)은 웹페이지가 직접 칠할 수 없는 시스템 영역이라 `html`·`body` 배경이나 `theme-color`를 바꿔도 그대로였습니다(고급설정 화면 정보: 안전영역 우 0). iOS 26 이후 Safari는 이 영역을 **화면 가장자리에 닿은 `position: fixed` 요소**를 보고 칠합니다(가장자리 한가운데에서 4px 안쪽에 닿고 그 가장자리를 90% 이상 덮어야 하며, 요소가 10px보다 얇으면 가장자리 4~6px 안쪽의 화면 픽셀 색을 따옴 — v35의 4px 띠는 그 자리가 책 카드여서 종이색이 번졌음). 그래서 화면 맨 오른쪽(머리줄 위)과 맨 왼쪽(설교노트 탭 아래)에 **폭 7px의 책상색 띠**(`.desk-edge`, 터치는 통과)를 두었습니다. 본문 글자는 가장자리에서 8px(`SIDE_PAD`) 안쪽에서 시작하므로 글자를 가리지 않고(점검으로 확인), 책 카드는 양 끝이 7px 안쪽에서 끝나 보입니다. 글자 위치·쪽 나누기는 그대로입니다. **(v37)** v36 실기기에서 띠 색이 세피아(#CDBA90)로 바뀐 것을 확인했습니다(페이지가 칠한 색이 읽힌다는 뜻). 다만 야간으로 바꿔도 띠가 세피아로 남았으므로, 테마·책상을 바꿀 때, 앱을 켜고 다시 열 때, 화면 크기가 바뀔 때(접기/펴기) `theme-color` meta와 가장자리 띠(`#desk-edge-l/r`)를 **새 노드로 갈아 끼워**(`refreshSystemColor`, 곧바로 + 0.15초 + 0.7초 뒤) iOS가 색을 다시 읽도록 했습니다. 색이 같으면 반복하지 않습니다. 쪽 나누기·글자 위치는 그대로입니다. **고급설정 → 화면 정보**에 기기 화면 폭·배율·앱 버전(`APP_VER`)이 나오니, 새 버전이 적용됐는지 거기서 확인하세요.

'지도에서 고르기' 중에는 창이 숨고 십자가 지도 한가운데에 놓입니다. 확대·축소 단추는 오른쪽 위로, 내 위치 단추는 그 아래로 옮겼습니다. 키보드가 올라오면 떠 있는 창만 위로 올라가고 지도·아래 줄은 그대로입니다. ④ **세로 아이폰·듀오 접힘, 가로로 눕힌 아이폰(높이 520px 미만)** 은 이전처럼 '목록 | 지도' 탭 배치입니다. 펼침↔좁은 화면으로 바뀔 때 검색·키워드·내 위치 부품은 DOM 자리를 옮겨 갑니다(`mpPlace`). 이 변경은 웹 화면만 바뀌며 Swift 동작은 그대로입니다(앱 이름 표기만 v49).
- **모임 장소 지도 그림을 앱 테마에 맞춤(v50):** ① **지도 바탕을 테마별로** 바꿨습니다. 설정 → 고급설정 → '모임 장소 지도 그림'에 **CARTO 무료 열쇠(API 키, 이메일로 받음·계정 불필요)** 를 붙여 넣으면, 종이·세피아는 밝고 도로가 옅은 Positron(`light_all`)에 따뜻한 색조를, 야간은 Dark Matter(`dark_all`)에 어두운 회청색 색조를 입힌 지도가 보입니다(`MP_CARTO_STYLE`, 타일은 18단계까지, `?key=` 붙음). **열쇠가 없으면** 지금처럼 OpenStreetMap 바탕이며 테마별 색조(CSS 필터)만 입힙니다(야간은 기존 반전). 열쇠는 이 기기(`bf.mapkey`)에만 저장하고 **데이터 백업에는 들어가지 않으며** 저장 뒤에는 화면에 다시 보이지 않습니다. ② 지도 위 **확대·축소·내 위치 단추**(흰색→앱 바탕색), **출처 링크**(파란색→강조색), **핀 테두리·컵**(흰색→앱 바탕색), **내 위치 점**(테마별 파랑 `--mp-me`), 지도 그림이 뜨기 전의 바탕색(`--mp-land`)을 테마 색으로 맞췄습니다. ③ 바탕을 못 받을 때의 안내문은 열쇠를 쓰는 중이면 열쇠 확인까지 알려 줍니다. ④ 테마를 바꾸면 지도 바탕이 바로 따라 바뀝니다(`themeHooks` → `mpApplyTile`, 바뀐 것이 없으면 지도를 건드리지 않음). 오른쪽 아래 **출처 표기('© OpenStreetMap contributors, © CARTO')는 이용 조건이라 항상 남겨 두어야 합니다.** 색조 필터 값은 타일의 근사 색으로 계산해 정했으므로 실기기에서 보고 조정합니다(`style.css`의 `.mp-src-carto`·`.mp-src-osm` 규칙). Swift 동작 변경은 없고 앱 이름 표기만 v50입니다.
- **모임 장소 지도 — 벡터 방식(B) 추가(v51, 비교용):** 설정 → 고급설정 → '모임 장소 지도 그림'에서 지도를 그리는 방식을 **래스터(A, 기본)** 와 **벡터(B, 시험)** 중에서 고를 수 있습니다. 벡터는 OpenFreeMap(키 없는 공개 서버)의 OpenMapTiles 벡터 타일을 MapLibre GL이 앱 안에서 직접 그리며, 도로·건물·물·공원·글자 색을 테마별(종이·세피아·야간)로 `mapstyle.js`에서 정합니다(래스터처럼 색조 필터를 덧입히는 것이 아닙니다). 핀·확대/축소·내 위치 단추·카드는 그대로 Leaflet이 맡고 **바탕 층만** 바뀝니다(`leaflet-maplibre-gl` 연결 플러그인). 벡터 부품(`lib/maplibre-gl.js`·`maplibre-gl.css`·`leaflet-maplibre-gl.js`, `mapstyle.js`, 약 1.1MB)은 **벡터를 고르고 지도를 열 때만** 불러오므로 래스터 사용자에게는 영향이 없습니다. 한글 지명은 글자 파일(glyph) 대신 기기 글꼴로 그립니다(MapLibre 기본 동작, 한글 음절·자모 범위 포함). 이 기기에서 벡터가 안 되면(WebGL2 없음 · 부품/자료를 못 받음 · 15초 안에 첫 그림이 안 나옴) **그 실행 동안 자동으로 래스터로 돌아가고** 안내문을 띄우며, 설정의 방식 단추를 다시 누르면 한 번 더 시도합니다. 선택값은 `bf.mapeng`로 **이 기기에만** 저장하고 데이터 백업에는 넣지 않습니다. 출처 표기는 'OpenFreeMap © OpenMapTiles Data from OpenStreetMap'입니다. 벡터 방식에서는 CARTO 열쇠를 쓰지 않습니다. 시험은 `tests/map5.mjs`(가짜 벡터 타일 `tests/vtscene.mjs`)입니다.
- **모임 장소 지도 — 벡터(B)를 기본으로 고정(v52):** 사용자가 아이폰 듀오 실기기에서 v51의 벡터 방식(실제 OpenFreeMap 자료·한글 지명·종이 테마 색·출처 표기)을 확인하고 B를 기본으로 정했습니다. 이제 `bf.mapeng` 저장값이 없으면 **벡터**로 열리고(`mpEngGet`), 래스터(A)는 ① 벡터가 안 될 때의 **자동 복귀 대상** ② 고급설정에서 직접 고르는 **비상용**으로만 남습니다. 고급설정 단추 이름은 '벡터 (B) · 기본' / '래스터 (A) · 비상용'이고, CARTO 열쇠 구역은 '래스터(A) 지도 열쇠 (비상용)'으로 이름을 바꿨습니다(동작은 v50과 같음). A 코드·열쇠 입력 화면은 안전망으로 일부러 남겼으며, 정리하려면 `mpTileCfg`·`MP_CARTO*`·열쇠 UI·`.mp-src-carto/.mp-src-osm` CSS를 걷어내면 됩니다. 시험은 지도 래스터 경로를 보는 map1~4가 `bf.mapeng='raster'`로 시작하도록 고쳤고, map5는 '아무것도 안 골랐을 때 벡터'를 확인합니다.
- **모임 장소 화면의 위·아래 여백을 같게(v53):** 아이폰 듀오 펼침에서는 위쪽 안전영역이 없고 아래쪽(홈 막대)만 있어, 화면이 위로 쏠려 위 여백 약 12px · 아래 여백 약 48px 이었습니다. 이제 아래 여백이 더 클 때 **그 차이의 절반만큼 화면 전체(검색 줄·키워드·지도·아래 줄)를 아래로 내려** 위 30px · 아래 30px 로 맞춥니다(두 여백의 합은 그대로이고 지도는 약 11px 커집니다). 오른쪽 위 상태 알약 자리와 키워드~지도 간격(10px 이상)은 그대로 지킵니다. 위쪽 안전영역이 더 큰 기기(노치 아이폰 세로 등)와 iPad는 위를 더 줄일 수 없으므로 바뀌지 않습니다. 코드는 `app.js`의 `layoutMp`(`drop`). 시험은 `tests/map6.mjs`.
- **모임 장소 지도에 스타벅스·투썸플레이스 매장 층(v54):** 지도 오른쪽(내 위치 단추 아래)의 **커피잔 단추**로 켜고 끕니다(기본 켬, 이 기기만 기억·백업 제외). 지도를 확대(기준 13단계 이상)하면 전국 매장이 **작은 점**(스타벅스 초록 · 투썸 빨강 계열, 테마에 맞춰 밝기 조정)으로 보이고, 점을 누르면 이름·주소·내 위치에서의 거리와 **네이버·애플·구글 지도 길찾기**가 나옵니다. **[내 장소로 추가]**를 누르면 이름·주소·위치가 미리 채워진 '카페 추가' 입력 화면이 열려 전화·메모 등을 더해 저장할 수 있고, 이미 내 목록에 있는 곳(40m 안의 같은 브랜드)은 '내 장소에 있음'으로 표시됩니다. 매장 자료는 **내 카페 목록·백업과 따로**이며 앱 안의 `data/brandcafes.json` 에서 읽어 점은 인터넷 없이도 보이지만 지도 바탕은 인터넷이 필요합니다(이 파일이 없는 빌드에서는 '매장 자료를 불러오지 못했습니다'라고 안내하고 나머지 기능은 그대로). 자료 출처는 공공데이터포털 '소상공인시장진흥공단 상가(상권)정보'(분기 갱신, 이용허락범위 제한 없음)이며 **이름·주소·좌표만** 있고 전화·영업시간은 없습니다. 최근 폐점·이전은 늦게 반영될 수 있어 카드에 '영업 여부·시간은 지도 앱에서 확인'을 적었습니다. 한 화면에 900곳이 넘으면 가운데에서 가까운 900곳만 그립니다. 자료 파일은 PC에서 `scripts/filter-brand-cafes.py` 로 만듭니다(다음 갱신 때도 같은 방법). 이 버전에 들어 있는 자료는 **2026-09 기준 3,781곳**(스타벅스 2,256 · 투썸플레이스 1,525)입니다.
- **지도를 멀리 볼 때 안내 문구 변경(v55):** 모임 장소 지도를 확대 13단계 미만으로 줄이면 매장 점이 숨겨지는데, 이때 지도 위에 뜨는 안내를 '지도를 확대하면 스타벅스·투썸 매장이 보입니다'에서 **'지도를 확대하면 장소가 보입니다'**로 바꿨습니다.
- **세부 수정 3가지(v56):** ① 모임 장소 지도를 멀리 볼 때 뜨는 안내 문구('지도를 확대하면 장소가 보입니다')가 왼쪽 목록 창을 뺀 영역이 아니라 **지도 전체의 가운데**에 놓입니다. ② **'＋ 카페 추가' 단추가 '＋ 장소 추가'**로 바뀌었고, 그 단추로 여는 입력 화면의 제목도 '장소 추가'입니다(저장된 장소를 고치는 화면의 '카페 정보 수정'과 안내문 속 '카페' 표현은 그대로). ③ **아이폰 앱 펼침 화면에서 책장이 넘어갈 때 들린 쪽의 윗부분이 책 위쪽 가장자리에서 한 줄로 잘려 보이던 문제**를 고쳤습니다. 책을 잘라 내는 창을 위쪽으로만 15px(머리줄과 책 사이 간격 안쪽) 넓혀 책장이 넘어가는 동안 그 안에서 모두 보이게 했고, 대신 넘길 때 모서리를 들어 올리는 높이(접힘선의 기울기)를 그 안에 들어오도록 줄였습니다(탭·키보드로 넘길 때 쪽 높이의 10% → 최대 약 23px, 손가락으로 끌 때도 같은 상한). 그래서 접힘선이 이전보다 조금 덜 비스듬합니다. 웹(PC 브라우저)은 책 카드 그림자가 있어 이전 그대로입니다.
- **새 버전으로 바꿀 때:** 새 폴더를 올린 뒤, 아이폰에서 앱을 **두 번 열었다 닫으면** 새 버전이 적용됩니다. (앱을 직접 고쳤다면 `sw.js` 맨 위 `CACHE = 'bibleflip-v52'`의 숫자를 올려야 기기에 반영됩니다.) Netlify에서는 새 주소가 생기지 않도록 기존 사이트의 배포(Deploys) 화면에 폴더를 끌어다 놓으세요.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `index.html`, `style.css` | 화면 |
| `app.js` | 쪽 나누기, 책 넘김, 접힘/펼침 전환, 책·장 선택, 설정 |

## GitHub Pages로 올리기 (무료, 크레딧·배포 횟수 제한 없음)

1. github.com에 로그인 → `New repository` → 이름은 영문 소문자(예: `bible`), **Public**으로 만듭니다. (무료 계정의 Pages는 공개 저장소에서만 됩니다)
2. 저장소 화면에서 `Add file` → `Upload files` → 압축을 푼 폴더를 **열어서 안의 내용물 전체**(`index.html`, `app.js`, `data`, `fonts`, `icons`, `lib` …)를 끌어다 놓고 `Commit changes`. (폴더 자체를 놓으면 `index.html`이 한 단계 안쪽에 들어가 사이트가 열리지 않습니다)
3. `Settings` → `Pages` → Source `Deploy from a branch` → Branch `main` / `/ (root)` → `Save`. 1~2분 뒤 맨 위에 `https://아이디.github.io/저장소이름/` 주소가 나옵니다.
4. 아이폰 Safari에서 그 주소를 열고 `공유` → `홈 화면에 추가`.
5. 수정본을 올릴 때는 같은 방법(`Add file` → `Upload files`)으로 바뀐 파일을 올리면 같은 이름의 파일이 덮어써집니다. `sw.js`의 `CACHE` 숫자를 올린 뒤, 게시(1~2분)가 끝나면 앱을 두 번 열었다 닫으세요.
